# 内容生成边界

## 触发

| 允许 | 禁止 |
|------|------|
| 用户明确要求补/改/加深 | 闲聊「顺手」扩模块 |
| 有效标注（pending 且未 processed） | inbox 空仍大改题库 |
| 修有误、补缺段、补先修断裂 | 无请求全库重写 |
| 用户明确要求专家级梳理/重生成 | （此时允许按模块重写，仍须 EXPERT_DEPTH） |

默认**最小改动**；扩大范围须用户确认。  
**深度不打折**：即使用最小改动，改到的段落也必须达到 `docs/EXPERT_DEPTH.md`。

## 类型与产物

- knowledge / qa / algo / glossary / agent-inbox 各写各的；禁止写串型。
- 个人标注只进 `agent-inbox/`，不写进题库正文。
- 新英文术语才进 `glossary.yaml`（`phonetic` + `speak`）；不确定音标则留空或只写 speak，禁止假 IPA。

## 范围

- 只落主考模块；不擅自新建 module。
- 能并入旧篇不新开；新开须独立单元 + requires/order。
- 跨模块可回指，禁止大段复制。

## 深度与篇幅（单次）

- **地板（专家）**：见 `EXPERT_DEPTH.md`——可口述机制、边界、错误对照、带追问的坑。  
- **标注场景天花板**：默认只动标注涉及章节；整篇/全库专家重生成须用户明示（本次若已明示则按模块推进）。  
- 禁止：为凑段注水、加长「明白」章节、同义反复、词条式「专家腔」。

## 配图

- 仅当结构/时序用文字难懂时加图；不强制每篇有图。
- 资源进 `public/assets/diagrams/`；Markdown 相对路径 `./assets/diagrams/...`。
- 不加装饰图、表情包、无关截图。

## 事实

- 可写：与官方语义、已审 `_full`、常见共识一致的内容。
- 慎写：版本绑死细节 → 注明前提或「待核实」。
- 禁写：编造 API/行为、假实测、无依据清单堆砌。

## 交付停止点

1. 源文件已改（优先 `_full`）  
2. 需要时已跑 apply + `npm run content`  
3. 正文变更 → `version +1`（只改 priority 可不升）  
4. **禁止改 `id`**（新建才新 id）  
5. 回报：`id`、章节、新 version、（若有）`syncId`、自检结果  
6. 不擅自 commit / push / 标 processed（用户要求或标注任务约定时除外）  

## 总界

只在授权或有效标注下，按正确模块与篇幅，用最小改动把「不懂」降到可口述；不扩范围、不编事实、不改发布产物、不把类型写串。
