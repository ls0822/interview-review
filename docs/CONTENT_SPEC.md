# 内容规格（形态 / 台阶 / 放置）

改 `review-content/` 时遵守本文。硬摘要见 `AGENTS.md` 与仓库上级 `.cursor/rules/`。本文位于 `docs/`，不进 content-pack。

**深度默认标准**：`docs/EXPERT_DEPTH.md`（专家级掌握；生成时即按此写，不是事后补课）。

## 三种类型

### knowledge（知识点）

- **标题**：主题名，**禁止问句**（不要「什么是…」「如何…」）。
- **必含七段**（二级标题原文）：

  1. 一句话  
  2. 组成与结构  
  3. 原理  
  4. 使用与实践  
  5. 例子  
  6. 画面  
  7. 常见坑（或「常见坑与追问」）

- **篇内台阶**：一句话锚点 → 组成只亮零件 → 原理「直觉→机制→边界」一点一进 → 使用 → 例子服务原理 → 画面收束隐喻 → 坑=错法→追问。
- **术语延后**：新词首次出现用已知词解释；禁止首段连丢大量新词。
- **画面**：默认保留 ASCII 结构示意（脑内可画）。**按需**再加示意图（流程图/架构图），见下方「配图规则」。UI 可能显示为「结构示意」。

### 可读性（默认，协程试点已按此）

禁止「一大段只有概念、代码甩到文末」。**原理 / 使用**里每个可独立口述的点，用三级标题拆成**知识单元**，单元内固定四块（可省略空块，顺序固定）：

1. **是什么**（人话，禁止堆术语）  
2. **看代码**（紧跟最小片段；没有代码就写「口述手势」）  
3. **和谁有关**（链到先修/后续 `` `kp-xxx` ``，或「同篇上一单元」）  
4. **别混**（和易混概念差在哪；一句够）

约束：

- 一句话仍要短；细节进单元，不在开场塞满。  
- 组成与结构：零件表 + **关系一句**；不要在组成里讲完原理。  
- 例子段：只保留「串场景」或「对照错法」；单元里已出现过的代码不要整段再贴一遍。  
- 单篇原理单元建议 4～8 个；每个单元正文宜短于一屏。  
- UI 会把 `###` 收成子卡片；不要用粗体假标题代替 `###`。

## 配图规则（按需，不篇篇加）

**该加图**（Agent 自行判断，优先 P0）：

- 多部件关系（线程/协程/续体、Job 树、Dispatcher 切换、触摸分发路径等）
- 时序/状态跳转用文字难一眼看清
- 用户「不懂」反复卡在结构关系上

**不必加图**：纯定义、短对比、清单、算法题面。

落地：

1. 图放 `public/assets/diagrams/`（SVG 优先，清晰可缩放）
2. 正文用 `![说明](./assets/diagrams/xxx.svg)`，通常放在「画面」段，**保留**原有 text 示意作口述备份
3. 图与全文隐喻一致；禁止装饰性插图、禁止无标注的糊图
4. 单篇默认 0～1 张；确有需要最多 2 张

可选 frontmatter：

```yaml
requires: [kp-xxx]   # 先修篇 id
order: 20            # 模块内阅读序（数字越小越先）
```

### qa（问答）

- 标题与 `## 问题` 用问句。
- `## 答案` 短、可追问；可挂 `knowledge_ref`；**禁止**整篇粘贴 knowledge。

### algo（算法）

- `## 题目` + `## 答案`（思路/复杂度）；不要写成 knowledge 七段体。

## 新知识点：模块与篇幅

1. **模块**：按面试主考能力线选 `module`；不新建 module（除非用户明确要求）。
2. **并入旧篇**（默认优先）：只是缺一步/一例/一对比，或强依赖宿主且短。
3. **新开 kp**（须同时满足）：可独立成面试问法、能撑满七段、需单独进路线图。
4. 交卷必报：`module` / 新开或并入哪一节 / `requires`+`order`。

## 深度稿路径

- 有 `_full/<id>.md` 的模块：只改 `_full/`，再  
  `node scripts/apply-full-knowledge.mjs && npm run content`
- 无 `_full`：改模块目录下对应 md，再 `npm run content`。
- **禁止**手改 `public/content-pack.json`。

## 质量自检（改完必过）

形态：

- [ ] 一句话可当开场白  
- [ ] 原理非词条罗列；例子对应刚讲的点  
- [ ] 画面与全文隐喻一致  
- [ ] 坑含错法与追问  
- [ ] 未扩写用户已标「明白」的章节  
- [ ] 先修概念都在 `requires` 闭包内可解释  

专家深度（详见 `EXPERT_DEPTH.md`）：

- [ ] 原理覆盖正常路径 + 边界/失败 + 易混对比  
- [ ] 例子含错误对照  
- [ ] 坑含可追问句；能撑住资深面试第二问  
- [ ] P0 与专家加分点区分清楚（若适用）  

二次「不懂」同一段：必须降坡（拆步/换喻/加对比），禁止同文复读。
