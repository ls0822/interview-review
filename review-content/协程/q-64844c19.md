## 问题
两个任务都在同一个线程上跑，会交叉运行吗？

## 答案
**A：会「交替」，但不是像两个线程那样被操作系统抢着切；而是谁碰到挂起点，谁让路。**

#### 1. 先建立正确图景

```text
同一条线程（一个工人）上有两张工单：任务1、任务2

工人同一时刻只能干一张工单。
任务1 若一直算、一直不挂起 → 任务2 只能等着，不会被「抢占插入」。
任务1 挂起（如 delay）→ 工人空出来 → 可以去干任务2。
任务2 再挂起 → 工人又可以回去把任务1 的续体捡起来。
```

所以：

- **是协作式交替**（cooperative），不是线程那种时间片抢占（preemptive）。  
- 「交叉」发生在 **挂起点**，不是任意毫秒级强制切换。

#### 2. 例子

```kotlin
val dispatcher = Dispatchers.Main.immediate // 或同一个单线程 Dispatcher
val scope = CoroutineScope(dispatcher)

scope.launch {
    println("1-A")
    delay(100)      // 挂起，让出线程
    println("1-B")
}
scope.launch {
    println("2-A")
    delay(100)
    println("2-B")
}
// 常见打印顺序类似：1-A → 2-A →（各自 delay 后）1-B / 2-B
```

若改成：

```kotlin
scope.launch {
    println("1-A")
    // 没有 delay，只有狂算 3 秒
    heavyCompute()  // 不挂起
    println("1-B")
}
scope.launch {
    println("2-A")  // 往往要等任务1整段跑完才有机会
}
```

→ **不会**在计算中途交叉；任务2要等任务1把线程占用的这段跑完（或遇到挂起）。

#### 3. 和「两个线程」对比

| | 两线程 | 两协程同一线程 |
|--|--------|----------------|
| 谁决定切换 | 操作系统可抢占 | 代码跑到挂起点才让 |
| 同一时刻 | 可真并行（多核） | **同一线程上不能真并行**，只能交替 |
| 一直占着算 | 另一线程仍可能跑 | 另一协程**跑不了**（除非你挂起/切走） |

#### 4. 若任务 1 是个循环，任务 2 会不会一直执行不到？

**分两种循环：**

| 循环长什么样 | 任务 2 能否跑到 |
|--------------|-----------------|
| 死循环/紧循环，**中间没有挂起**（纯 `while` 里狂算、狂打印） | **基本执行不到**（同线程上被任务 1 占死） |
| 循环里有 `delay` / `yield()` / `withContext` / `await` 等挂起 | **能穿插执行**（每次挂起都让路） |

```kotlin
// ❌ 同线程上会堵死其它协程
launch(Dispatchers.Default) {
    while (true) {
        doCpuWork() // 不挂起
    }
}

// ✅ 每圈让一让，别人有机会跑
launch(Dispatchers.Default) {
    while (true) {
        doCpuWork()
        yield()     // 主动挂起让出线程
        // 或 delay(1)
    }
}
```

补充：

1. `yield()` 就是专门「我先歇一下，让同 Dispatcher 上其它协程跑」的挂起。  
2. 若任务 1 在 `Dispatchers.Default`（线程池）上死循环占满**所有**工作线程，其它协程也会饿；所以 CPU 狂算还要控制并行度。  
3. 取消：紧循环里要加 `ensureActive()`，否则 `cancel()` 了还在转。

#### 5. 面试怎么说

「同一线程上的多个协程是协作式调度：只有挂起时才切换。若一个协程写无挂起的死循环，同线程其它协程会饿死；循环里应 `yield`/`delay`，并 `ensureActive` 响应取消。」
