## 问题
`launch`、`async`、`withContext` 怎么选？

## 答案
`launch` 启动一张不要返回值的工单，给你一个 `Job`，用来取消或 `join` 等待结束。异常会往父协程抛。

`async` 启动一张要结果的工单，返回 `Deferred`。调用 `await()` 才会拿到值，异常也推迟到 `await`。两个接口都要：

```kotlin
coroutineScope {
    val a = async(Dispatchers.IO) { api.a() }
    val b = async(Dispatchers.IO) { api.b() }
    show(a.await(), b.await())
}
```

`coroutineScope` 会等里面的子协程都结束才往下走。其中一个失败，另一个会被取消，异常交给调用方。产品允许只展示成功的那一半时，换成 `supervisorScope`，各自 try/catch。不要开两个 `launch` 再写两个共享变量，结束时机和异常都散了。

`withContext` 不新开一条并行工单。它是同一张工单临时换工人，干完自动换回来。下一行一定在回来之后执行。`launch(Dispatchers.IO)` 是另外一条工单，和当前这行并发，不会把结果交到下一行。

`GlobalScope` 没有主人。页面关了，它还能跑，也能漏回调到已销毁的界面。
