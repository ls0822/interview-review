## 问题
取消为什么有时取消不掉？父子和监督怎么分？

## 答案
`cancel()` 只是把 Job 标成取消中。协程跑到下一个挂起点，挂起函数发现取消，抛 `CancellationException`，协程才停。`CancellationException` 是正常结束信号，不是业务失败。

取消不掉的三种代码：

```kotlin
// 1. 不挂起，检查点永远到不了
while (true) { crc32(buffer) }

// 应写成
while (isActive) {
    crc32(buffer)
    ensureActive()
}

// 2. 把取消信号吃掉，协程会继续跑完
try {
    withContext(Dispatchers.IO) { load() }
} catch (e: Exception) {   // CancellationException 是 Exception 的子类
    log(e)
}

// 应先放行
try {
    withContext(Dispatchers.IO) { load() }
} catch (e: CancellationException) {
    throw e
} catch (e: Exception) {
    log(e)
}
```

第三种：`GlobalScope.launch` 或另一个自己建的 Scope，父页面取消影响不到它。

结构：

- 父取消，所有子取消。
- `launch` 的子协程抛了普通异常，默认父也失败，兄弟被取消。
- `SupervisorJob` 或 `supervisorScope`：一个孩子失败，只影响这个孩子，兄弟继续。页面上「推荐」和「消息」两块请求互不影响时用它。
- `async` 的异常存在 Deferred 里，不 `await` 就暂时不抛。如果这个 `async` 的父是普通 `coroutineScope`，失败仍然会取消兄弟。
