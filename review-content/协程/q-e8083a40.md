## 问题
`Channel`、`Mutex`、限流

## 答案
`Channel` 是协程之间的队列。`send` 在缓冲满时挂起，`receive` 在空时挂起。`capacity = 0` 时，发送方必须等接收方同时在场，这叫会合。`capacity = UNLIMITED` 时内存会涨。适合「信令入队、单线程按序执行」：多个生产者 `send`，一个消费者 `for (signal in channel)`。

`Mutex` 用来保护协程之间的共享变量。和 `synchronized` 的两个差别要讲出来：

1. `synchronized` 阻塞线程。`Mutex.withLock` 挂起协程，线程可以去干别的。
2. `synchronized` 可重入，同一条线程能再次进入。`Mutex` 不可重入，同一条协程再次 `withLock` 这把锁，会永远等自己。

`withLock` 里面写了 `delay` 或 `withContext`，锁不会放开。别人一直等。范围要只包住改共享变量的那几行。

同时最多 3 个下载：

```kotlin
val gate = Semaphore(3)
scope.launch {
    gate.withPermit { download(id) }
}
```

`Semaphore` 的许可取走后，别的协程在 `withPermit` 处挂起，不是阻塞出第 4 条线程。

## 2. Java 并发与集合

先分清三件事，面试官说「线程安全」时往往混在一起问：

| 问题 | 出了什么事 | 谁来解决 |
|--|--|--|
| 原子性 | 一步被拆开，中间插入了别人 | 锁或原子类 |
| 可见性 | A 线程写了，B 一直看见旧值 | `volatile`、锁、`final` |
| 有序性 | 编译器和 CPU 把读写换了顺序 | `volatile`、锁 |
