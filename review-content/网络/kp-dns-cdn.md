## 一句话

DNS 把域名变成 IP，系统解析可能慢、被劫持或拿着过期缓存。HTTPDNS 改用 HTTPS 问一份可信的解析，再拿 IP 去连，但证书和 Host 仍必须用域名。CDN 把静态资源和安装包放到离用户近的节点，客户端要处理回源失败、防盗链和 HTTPS。

## 组成与结构

一次普通请求里，DNS 和 CDN 发生在业务字节之前：

```text
域名 → DNS 得到 IP → TCP/TLS 连到这个 IP → HTTP
                ↑
         若域名是 CDN，这个 IP 是边缘节点
         边缘没有内容时才回源
```

| 手段 | 解决什么 | 新的注意点 |
|------|----------|------------|
| 系统 DNS | 通用、无额外依赖 | 慢、劫持、本地缓存陈旧 |
| HTTPDNS | 用 HTTPS 拿解析结果，绕过本地 DNS | IP 直连时的证书名、SNI、Host |
| 多 IP 与备份域名 | 一个地址失败就换 | 要有次数上限，避免把所有地址试一遍把超时加很长 |
| 预解析 | 进页面前先拿到 IP | 预解析结果也会过期 |
| CDN | 边缘缓存，就近下载 | 回源失败、防盗链过期、证书是 CDN 域名 |
| 缓存解析结果 | 少一次查询 | 要有 TTL，不能永远用旧 IP |

离线包、图片、安装包走 CDN 域名。接口 API 是否走 CDN 看它能不能缓存。个性化接口放在边缘上，要么命中不了，要么把别人的响应给出去。

## 原理（深度，分步骤，讲清为什么）

**1. 系统 DNS 慢和被劫持时发生了什么**

客户端把域名交给系统解析器，解析器去问运营商的递归 DNS。这一问可能要几百毫秒，弱网时还会超时。运营商或局域网可能把结果改成自己的广告页或错误 IP，这就是劫持：TCP 甚至能连上，但内容不是你的服务器。本地还有一层缓存，权威那边已经把机器换了，客户端仍拿着旧 IP，会连到已经下线的节点，表现为间歇失败。

这些都不是 TCP 握手能解决的。握手只是连向你拿到的那个 IP。

**2. HTTPDNS 为什么能绕过，又为什么容易把 HTTPS 搞坏**

HTTPDNS 的查询本身走 HTTPS，访问一个你信任的解析服务，返回域名对应的 IP 列表。业务连接直接连 IP，不再问本地 DNS，劫持和局部 DNS 故障就绕开了。解析结果仍要缓存，并遵守返回的 TTL，否则每次请求都多一次 HTTPS。

连上之后 TLS 要校验证书里的名字。证书签的是域名，不是 IP。所以：

- TCP 的目标地址用 IP。
- TLS 的 SNI 填原来的域名，服务器才能选出正确的证书。
- 证书校验用域名。
- HTTP 的 Host 头用域名，源站和 CDN 靠它区分虚拟主机。

四件里少一件，就会证书错误、连到默认站点，或 CDN 返回 404。不要把 URL 写成 `https://1.2.3.4/` 就结束。

多 IP 时，一个 IP 连接失败再换下一个，失败要计入这个 IP 的熔断，短时间内不要反复撞同一个坏地址。备份域名是另一条独立的 DNS 名字，主域名整体异常时才换，避免主域名只是慢、备份域名又增加一倍流量。

**3. CDN 在网络里的位置**

源站只有一份内容。CDN 在各地有边缘节点。用户解析 CDN 域名时，权威 DNS 或调度按地域返回近的节点 IP。节点有缓存就直接传；没有就回源，再缓存起来。对客户端，这仍然是一个 HTTPS URL，只是主机名指向边缘。

离用户近，往返时间小，大文件和图片会明显快。动态接口如果每个人的响应都不同，边缘缓存帮不上忙，还多一跳。

**4. 回源失败、防盗链、HTTPS 各自失败成什么样**

回源失败：边缘还在，源站挂了或边缘到源站的网络断了。用户能连上 CDN，却收到 5xx 或很慢。这时换一个边缘 IP 可能没用，要降级到备用域名或稍后再试，并打点区分「连不上边缘」和「边缘连不上源」。

防盗链：URL 上带过期时间戳和签名。过期后边缘拒绝，这是 403，不是网络超时。客户端时钟不准、或者把带签名的 URL 缓存太久，都会成片 403。重试同一个 URL 没有意义，要重新向自己的服务器要一次地址。

HTTPS：边缘要有覆盖这个 CDN 域名的证书。证书错误不要降级成 HTTP。图片和离线包都一样。

**5. 和连接优化的关系**

预解析、预连接是为了把 DNS 和握手挪到用户点击之前。CDN 域名和 API 域名通常不同，预连接要针对真正会用到的主机，对一个用不到的域名预连接只是浪费。HTTPDNS 的缓存和 OkHttp 的连接池是两层：前者省掉解析，后者省掉到这个 IP 的重复握手。IP 变了，旧连接不能复用。

预解析和预连接只针对马上要用的主机。CDN 域名和 API 域名通常不是同一个，对用不到的域名预连接只会占着池子。解析缓存遵守 TTL，连续失败就丢掉这条 IP，避免一直撞已经摘掉的节点。下载成功仍要校验内容，边缘返回 200 也可能是截断的包。403 重新签发 URL，不要当成超时去换 IP。

IP 只决定 TCP 连哪一台机器。SNI、证书校验和 Host 必须仍是域名，否则要么握手失败，要么进错虚拟主机。解析缓存过了 TTL 还继续用，就会一直连已经下线的节点。

备份域名是主域名整体异常时的退路，不要主域名只是慢就同时把流量打到两条名字上。

个性化接口通常不要套 CDN，边缘命中不了，还多一次回源。

连续连接失败要丢掉这条解析缓存。

## 使用与实践

图片、离线包、差分包使用 CDN 域名，URL 由服务端签发并带上有效期。下载失败按错误码分：超时换 IP，403 重新签发，校验和不对则丢弃文件不要安装。离线包的成功率要单独看，不要和接口成功率混成一个「网络成功率」。

API 用 HTTPDNS 时，OkHttp 需要自定义 DNS 或连接层，把「按域名建连」换成「连 IP 但按域名做 TLS」。证书锁定如果锁的是旧证书，CDN 换证会全量失败，针脚要能更新。

不要在客户端写死 IP。地址会变，写死的 IP 会在调度调整后全部失败。备份域名可以写在配置里并允许下发更新。

监控至少分：DNS 耗时、连接耗时、TLS 耗时、首字节、总时间、HTTP 状态、是否走了备份域名。没有分段就无法判断该优化解析还是该换 CDN。

## 例子（至少 1 个完整代码或伪代码块 + 边界场景）

解析和请求分开。连接用 IP，身份仍用域名：

```kotlin
class HttpDns(private val api: DnsApi) : Dns {
    override fun lookup(hostname: String): List<InetAddress> {
        val cached = cache.getIfFresh(hostname)
        if (cached != null) return cached
        val ips = api.resolve(hostname) // 这一下自己走 HTTPS，不用本地 DNS
        cache.put(hostname, ips, ttl = ips.ttl)
        return ips.addresses
    }
}

fun request(domain: String): Request {
    return Request.Builder()
        .url("https://$domain/pkg/v3.zip") // 主机名保持域名，DNS 层再换成 IP
        .build()
}
```

若底层只能拿到 IP 再自己建连，SNI 和 Host 仍填 `domain`，证书校验也用 `domain`。

下载 CDN 资源时把三类失败分开：

```kotlin
when (result) {
    is Timeout -> ipPool.markFail(ip)          // 换 IP 再试，有上限
    is Http403 -> url = signer.refresh()       // 防盗链过期，不要连重试
    is ChecksumMismatch -> file.delete()       // 不要安装坏包
    is CertError -> reportAndStop()            // 不要降级成明文
}
```

边界一：本地 DNS 把域名劫持到广告 IP。TCP 能连通，页面内容不对，甚至证书直接失败。HTTPDNS 绕过这段解析。如果 HTTPDNS 接口本身还靠本地 DNS 找，它也会被劫持，所以 HTTPDNS 的接入域名要有可靠的到达方式，例如预置备用 IP 或只用已验证的通道。

边界二：缓存的 IP 过了 TTL 仍在用。节点已摘除，连接超时。缓存必须到期重新解析，连续失败还要主动丢掉缓存。

边界三：离线包 URL 带的时间戳过期。边缘返回 403。客户端若当成网络错误换 IP 重试，会把所有边缘都打一遍仍失败。应重新取 URL。

边界四：边缘返回了被截断的 zip，HTTP 状态仍是 200。没有校验和就会装上坏包。CDN 成功只说明字节下载完，不说明内容对。离线包要校验再替换本地版本，失败就回滚。

## 画面（text 结构图）

```text
普通：
  App → 系统 DNS → 运营商解析 → IP → 源站

HTTPDNS：
  App → HTTPS 问解析服务 → IP 列表（带 TTL）
     → 连 IP，但 SNI / 证书 / Host 仍用域名

CDN：
  App → 调度得到近的边缘 IP → 边缘有缓存则直接下发
                             → 没有则回源，再缓存

失败怎么分：
  解析失败 / 连接超时     → 换 IP、备份域名
  TLS 域名不匹配         → 检查是不是把证书校验做成了 IP
  403                    → 防盗链过期，重新签发
  边缘 5xx               → 回源问题，不是再解析一次就能好
  校验失败               → 丢掉文件，走重下或回滚
```

## 常见坑与追问（至少 3 条）

1. **HTTPDNS 拿到 IP 之后，URL 能不能改成 https://IP/ ？** 不能直接改。证书、SNI、Host 都认域名。IP 只用于把 TCP 连到哪台机器。四者拆开，HTTPS 才会既绕过本地 DNS 又校验通过。

2. **CDN 很快是不是就不用做校验？** 快只说明路径短。回源可能给了错误内容，连接也可能在中途被重置后留下半个文件。离线包和安装包必须校验，失败不能替换正在使用的版本。

3. **防盗链过期和网络超时怎么区分？** 过期是 HTTP 403，同一条 URL 重试没有用，要重新签发。超时是没有拿到完整响应，可以换 IP 或稍后再试。混在一个「失败」里会做出错误的重试。

4. **解析缓存越久越省，为什么要 TTL？** 调度会把故障节点摘掉。缓存不失效，客户端会一直连坏 IP。TTL 内可以复用，到期或连续失败要刷新。

5. **所有接口都套上 CDN 会不会更快？** 只有可缓存的公共内容受益。个性化接口在边缘命中不了，还多一次回源。图片、离线包、安装包适合 CDN；账号相关的动态接口通常直接访问 API 域名。
