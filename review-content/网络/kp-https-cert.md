## 一句话

HTTPS 是 HTTP 跑在 TLS 上。证书用来证明「对面这个公钥确实属于这张域名」，握手时校验链、域名和有效期，防止中间人。密钥协商用非对称或密钥交换，大量数据改用对称加密。

## 组成与结构

| 部分 | 作用 | 为什么不能少 |
|------|------|----------------|
| 证书 | 绑定公钥、域名、有效期，并由 CA 签名 | 只有公钥、没有可信签发，谁都能拿一对密钥冒充站点 |
| 证书链 | 站点证书 ← 中间 CA ← 根 CA | 设备只预置根，不会预置全世界每张站点证书 |
| 私钥 | 留在服务器（或持有者） | 泄露等于别人能冒充这张证书 |
| 对称密钥 | 握手之后加密业务数据 | 非对称算得慢，不适合每个字节都用 |
| SNI | 握手早期带上域名 | 一台机器多个证书时，服务器要知道拿哪张；IP 直连时这里必须仍是域名 |

客户端信任的是系统或应用预置的根证书。抓包工具要解密 HTTPS，得让设备信任它自己的根，由它在中间重新签发。证书锁定（Pinning）则是客户端额外记住「只认这把公钥或这张证书」，连用户新装的根也不认。

## 原理（深度，分步骤，讲清为什么）

**1. 只有加密、没有证书，防不住中间人**

非对称加密可以做到「用公钥加密的内容只有私钥能解」。如果公钥是对方当面给的，这够用。网络上对方先发来一把公钥，客户端无法分辨这把钥匙是服务器的，还是网关临时造的。中间人可以把自己的公钥给你，再拿服务器的公钥去跟服务器说话，两边都以为自己在和对方加密。

证书就是把公钥和域名写在一起，请 CA 用 CA 的私钥签名。客户端用预置的 CA 公钥验证签名，确认这份绑定没被改过，再核对域名是不是当前要访问的那个、有效期是否还在。链断了、域名不对、过期了，握手失败。这样中间人没有 CA 的私钥，签不出一张客户端会信的假证书。

**2. 为什么是链，不是一张证书**

根证书很少，而且寿命长，预置在系统里。站点证书又多又经常换。于是根签发中间 CA，中间 CA 签发站点证书。验证时从站点证书往上走，每一级的签名都能被上一级公钥验证，直到碰到本地信任的根。少任何一级，或者中间那级已经被吊销，都不该信任。

**3. 握手在交换什么**

现代 TLS 的具体报文不必背版本号，面试把目的说清：

1. 客户端说自己支持的版本和密码套件，并带上随机数。服务器多证书时，SNI 里放域名。
2. 服务器选定套件，下发证书链。双方验证证书。
3. 用密钥交换得到一份只有这两端能算出的共享秘密（历史做法里有用服务器公钥加密预主密钥；现在常见是椭圆曲线密钥交换，再结合证书证明服务器身份）。
4. 从这个共享秘密导出对称密钥。之后的 HTTP 数据用对称加密，并用消息认证码或 AEAD 保证没被改。

非对称（或密钥交换）只解决「怎么安全地得到一把共享钥匙，并确认对方身份」。对称加密解决「数据很多，算法必须快」。完整性要单独保证：只加密不认证，攻击者仍可能改密文。

**4. 抓包为什么有时能看到明文**

抓包工具在本机当代理，动态生成一张域名匹配的证书，并用用户安装的根去签。系统如果信任了这个根，校验链会通过，工具就能解密再加密。用户没安装这个根时，校验失败，App 应拒绝连接。

Pinning 是客户端写死或下发「服务器公钥的指纹」。即使链被一个用户根签过，指纹不对也断开。代价是换证书时，写死在包里的指纹会把旧版本全部打断，所以要么随配置下发，要么留备份针脚，并有过期策略。它防的是「用户机器上多了一张不该信的根」，也让正常抓包变难，线上排错要留可控的调试开关，不能在正式用户包里随便关校验。

**5. IP 直连时证书仍看域名**

HTTPDNS 拿到 IP 后，TCP 可以连这个 IP，但 TLS 要证明的是域名。证书里没有 IP，或者证书签的是别的名字，校验就会失败。正确做法是：连接地址用 IP，SNI 和校验用原来的域名，HTTP 的 Host 也用域名。只把 URL 换成 `https://ip/...` 而不处理 Host 和证书名，要么连不上，要么连上了错误的虚拟主机。

**6. 失败模式与易混**

校验失败（过期、域名不匹配、链断）重试同链路无效，应与连接超时分开打点；本机时间错乱也会让正常证书显示未生效/过期。TLS 止窃听与篡改，业务防重放仍靠 nonce/时间窗；只加密无完整性（非 AEAD）时密文仍可能被摆弄。Pinning 指纹宜配置下发，换证时避免旧包整批握手失败。

## 使用与实践

全站 HTTPS。敏感字段可以在 TLS 里面再加密一层，但不要自己发明算法替代 TLS。密钥不要硬编码在包里。日志里的 token、手机号脱敏。

防重放靠业务层的 nonce 或时间戳，TLS 不理解「这笔支付只能用一次」。证书过期要在服务端提前换，客户端要对「校验失败」单独打点，区分网络超时和证书错误。证书错误不要自动重试同一条链路，重试也过不了。

OkHttp 默认做系统信任的证书校验。自签环境只能出现在调试构建。Pinning 用网络拦截器或 CertificatePinner 这类机制，换证要有配置下发或发版计划。

离线包、上传如果走 CDN 的 HTTPS，证书域名是 CDN 域名，不是源站内网名。时间戳防盗链是 URL 参数，和证书不是一回事：证书证明你在和这个域名说话，防盗链证明这个 URL 还在有效期内。

## 例子（至少 1 个完整代码或伪代码块 + 边界场景）

IP 直连仍按原域名校验。伪代码对应 HTTPDNS 之后的请求：

```kotlin
fun buildCall(domain: String, ip: String, client: OkHttpClient): Call {
    val url = "https://$ip/v1/config".toHttpUrl()
    val request = Request.Builder()
        .url(url)
        .header("Host", domain) // 源站靠 Host 选虚拟主机
        .build()
    // 实际工程里还要用自定义 DNS 或 socketFactory，
    // 让 TLS 的 SNI 和证书校验使用 domain，而不是 ip
    return client.newCall(request)
}

fun pin(builder: OkHttpClient.Builder) {
    builder.certificatePinner(
        CertificatePinner.Builder()
            .add("api.example.com", "sha256/AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=")
            .build()
    )
}
```

边界一：证书昨天过期。TCP 是通的，失败发生在 TLS。错误码要记成证书校验失败，而不是连接超时。一直重试没有用，要换证或校正本机时间。本机时间被拨到几年前，正常证书也会显示为尚未生效或已过期。

边界二：用户安装了抓包根。没有 Pinning 的调试包会成功，能看到明文，这是预期。正式包如果做了 Pinning，这条抓包会失败。线上不能为了方便把校验关掉。

边界三：CDN 换了证书，包里的针脚还是旧的。所有固定针脚的旧版本请求失败，而系统浏览器是正常的。所以针脚要能下发，或同时带上一张下一张证书的备份针脚。

边界四：HTTPDNS 返回了 IP，代码把 URL 主机直接换成 IP，证书却是签给域名的。握手在校验证书时失败。Host、SNI、证书名必须仍是域名，IP 只用于建 TCP。

## 画面（text 结构图）

```text
客户端                         服务器
  |---- ClientHello（SNI=域名） →|
  |←--- 证书链 + 密钥交换 -------|
  |                              |
  本地信任库：站点证 → 中间 CA → 根
  核对：签名、域名、有效期
  |==== 对称密钥加密的 HTTP ====→|

没有证书时的中间人：
  客户端 ←→ 攻击者的公钥 ←→ 攻击者 ←→ 服务器的公钥 ←→ 服务器

Pinning：
  链即使被「用户安装的根」签过，公钥指纹不对也拒绝
```

## 常见坑与追问（至少 3 条）

1. **HTTPS 是不是把 HTTP 内容用服务器公钥逐字节加密？** 不是。公钥体系用来交换密钥并证明身份，数据用对称加密。非对称太慢，也不适合作为持续传输的唯一算法。

2. **装了抓包证书为什么就能看到接口明文？** 工具用你信任的根签发了一张域名对得上的证书，校验因此通过。它是合法地变成了中间人。Pinning 可以拒绝这张证书。正式环境不要关闭校验。

3. **证书校验通过，是不是业务就没有中间人、也没有重放？** 校验通过说明你在和证书对应的那一方说话，传输没被改。业务请求仍可能被原样重放。支付、登录态要有 nonce、时间窗和一次性序号。日志也不要把 token 打出来。

4. **IP 直连为什么会证书错误？** 证书签的是域名。只改连接 IP、不把 SNI 和 Host 留成域名，校验或虚拟主机会错。HTTPDNS 必须和证书校验一起设计。

5. **自签证书放进正式包行不行？** 正式用户没有理由信任你随包发的根，除非你把校验范围收得极窄并承担换证成本。调试构建可以单独信任，正式构建走公共 CA 或正常的企业证书链。
