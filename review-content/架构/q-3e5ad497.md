## 问题
MVVM 是什么？

## 答案
ViewModel **不拿 View**。它只暴露状态；界面订阅状态，自己决定怎么画。旋转后 ViewModel 还在，新界面重新订阅即可。

**下一页：** 点击调用 `viewModel.nextPage()`，里面 `_page.value = page + 1`。Compose 收到新页码就重组，XML 则用观察者改 TextView。

**举手：** 还是调用 `viewModel.raiseHand()`。发信令是动作，Toast 不能塞进「当前页码」这种状态里，否则一重组会再弹一次。所以 ViewModel 旁边再留一个一次性通道（`Channel` 或 `SharedFlow`，replay = 0），界面收到才 Toast。

```text
点击「举手」
  → viewModel.raiseHand()          // 界面直接点名这个方法
  → 发信令
  → effect.send(Toast("已举手"))   // 一次性
  → 若按钮要变灰，再改 State
```

和 MVI 相比，MVVM 允许界面知道方法名：`nextPage()`、`raiseHand()` 可以并存。简单页这样最清楚。

ViewModel 不持有 View，是为了配置变更后还活着，也不会把 Activity 泄漏在逻辑里。
