## 问题
MVI 是什么？和 Flow、Compose 什么关系？

## 答案
MVI 是单向流：**用户只发意图，逻辑只产出新状态或一次性效果，界面只负责画和转发点击。**

```text
点击 → Intent → ViewModel → 新的 State（界面数据）
                         └→ Effect（Toast、跳转、复制，做一次就扔掉）
```

Flow 和 Compose 不是 MVI 的定义。以前用 XML + LiveData，或者 RxJava，也叫 MVI。现在 Android 上例子大多是 `StateFlow` + Compose，所以看起来像绑在一起。

三条线不要混成一个 Flow：

| 线路 | 用什么 | 为什么 |
|------|--------|--------|
| 界面数据 State | `StateFlow` | 有当前值。旋转、重组后还能画出页码 |
| 用户意图 Intent | 密封类；多了再进 `Channel` | 描述「用户想干什么」，不是数据本身 |
| 一次性效果 Effect | `Channel` 或 `SharedFlow(replay=0)` | Toast、跳转做完即弃。放进 State 会再弹一次 |

Compose 用 `collectAsStateWithLifecycle()` 收 State。冷的 `flow { }` 没有当前值，不能当页面状态。
