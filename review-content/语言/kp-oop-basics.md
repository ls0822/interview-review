## 一句话

封装把变化关在类型里面，继承复用实现，多态让父类型引用在运行时走到子类重写；重载在编译期按参数选定，重写在运行期按对象选定。

## 组成与结构

三件事加上两个「同名」要分开背，Android 源码里全是这套：

| 概念 | 决定时机 | 看什么 |
|------|----------|--------|
| 封装 | 设计时 | 字段私有，只留方法 |
| 继承 | 编译期建立父子 | 子类拥有父类成员 |
| 多态 | 运行期 | 实际对象的重写方法 |
| 重载 overload | 编译期 | 方法名相同，参数列表不同 |
| 重写 override | 运行期 | 签名相同，子类换实现 |

Java 单继承、多实现。抽象类是「半成品的父类」：可以有字段、构造、已实现方法和抽象方法，适合抽模板（`is-a`）。接口是能力合同（`can-do`），Java 8 起可以有 `default` 方法，仍然可以多实现。Kotlin 的接口也能带默认实现，类默认 `final`，要继承必须 `open`，方法要被重写也必须 `open`。这是在减少随手继承造成的脆弱基类。

关键字：

| 关键字 | 作用 |
|--------|------|
| `final` 类 / 方法 | 不能继承 / 不能重写 |
| `final` 变量 | 引用不能再指向别处；对象内部仍可变 |
| `static` | 属于类，不依赖实例；Kotlin 用伴生对象表达 |
| `this` / `super` | 当前对象 / 父类那一份 |
| Kotlin `open` | 显式允许继承或重写 |

## 原理

1. **编译器如何选重载。** 它只看调用点的静态类型和实参类型，选出最具体的那个方法，写进字节码的调用目标。运行时对象是子类也不会改选另一个重载。所以 `f(null)` 在有 `f(String)` 和 `f(Integer)` 时可能编译失败，因为两个都匹配。
2. **重写如何分派。** 实例方法在字节码里是 `invokevirtual` / `invokeinterface`，按对象头里的类型指针找方法表。子类提供了相同签名（方法名、参数、返回协变）的方法，就占住这个槽。字段没有多态，父类引用访问的是父类字段。`static` 方法也没有多态，隐藏不是重写。
3. **`@Override` 的价值。** 它让编译器检查你是不是真的覆盖了父方法。签名写错一个参数，就会变成重载，父方法仍被调用，bug 很安静。Kotlin 重写必须写 `override`，写错签名直接编译失败。
4. **构造顺序。** 父类构造先完成，再子类字段初始化，再子类构造体。父类构造里调用可重写方法，会进子类实现，此时子类字段还是零值。所以构造函数里不要调用开放方法。
5. **可见性与重写。** 重写不能缩小可见性。Java `protected` 可以提到 `public`。Kotlin `internal` 的成员若要给 Java 继承体系用，要想清楚模块边界，它不是包私有。
6. **抽象类和接口的选择。** 需要持有状态、构造依赖、模板方法里固定骨架时用抽象类。需要给已经有父类的 Android 组件再挂能力时用接口，因为类只能有一个父类。`default` 方法冲突时，实现类必须自己覆盖，明确要哪一个。

## 使用与实践

SDK 的回调用接口，不要强迫宿主继承你的 Activity 基类。模板里固定流程（检查参数、打点、真正请求）可以放抽象类，把「真正请求」留成抽象方法。

Kotlin 给 Java 继承的类要标 `open`，给 Java 重写的方法也要 `open`，否则 Java 侧不能 `@Override`。数据模型优先 `data class` 组合，而不是一层套一层继承。

`final` 的集合引用仍可 `add`。若要内容也不变，用不可变列表或只暴露只读接口，并在文档里写清是不是防御性拷贝。

SDK 回调接口的方法保持少而稳定。新增能力用新接口，旧接口默认方法可以给 Java 8 以后的调用方兜底，但 Android 低版本和 Kotlin 混编时要在真机上编一次，避免 default 方法的字节码差异变成运行时找不到方法。Kotlin 侧重写 Java 方法时签名必须逐字对齐，包括可空注解，否则会变成另一个重载，父类方法仍被系统调用。

## 例子

```java
class Animal {
    void cry() { System.out.println("..."); }
    void feed(int n) {}
}
class Dog extends Animal {
    @Override void cry() { System.out.println("汪"); }
    void feed(int n, boolean extra) {} // 重载，不是重写
}
Animal a = new Dog();
a.cry();   // 汪，运行期
a.feed(1); // Animal.feed，编译期就定了
```

```kotlin
open class Base {
    open fun name() = "base"
}
class Child : Base() {
    override fun name() = "child"
}
```

`final List<String> list = new ArrayList<>(); list.add("a");` 合法，`list = new ArrayList<>()` 不合法。

## 画面

```text
编译期：看引用类型，选定重载签名
运行期：看对象类型，方法表找到子类重写

Animal 引用 --> Dog 对象
   cry()  ---------> Dog.cry
   字段名访问仍是 Animal 的字段
```

## 常见坑与追问

1. **重载重写说反。** 追问：`feed(int)` 和 `feed(int, boolean)` 是哪个？重载。同签名才是重写。
2. **父类构造里调开放方法。** 追问：子类字段为什么还是 null？因为子类构造体还没跑。解决：构造期不要回调子类。
3. **以为 final 变量等于不可变对象。** 追问：怎么做到内容也不变？不暴露可变引用，或拷贝后再给别人。
4. **Kotlin 类默认不能继承，Java 调用方编译失败。** 追问：要加什么？类和方法都要 `open`。和 Java 默认可以继承相反。
