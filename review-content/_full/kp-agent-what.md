## 一句话

补全模型只会根据当前上下文往下生成一段话；Agent 在之上加**可执行的反馈环**：选定工具 → 拿真实结果 → 写回上下文 → 再决策，直到达到停机条件或等人确认——差别是「能改环境」还是「只能编」。

## 组成与结构

四块积木（够扛 P0，不扯训练）：

| 块 | 职责 | 排查场景实例 |
|----|------|--------------|
| 模型 | 推理、规划下一步、写结论 | 结合日志与源码给可能原因 |
| 工具 | 读仓库外/仓库内的可验证动作 | 搜代码、拉日志、跑只读命令 |
| 上下文 | 本轮可见材料（有上限） | 现象、日志片段、相关源码、输出模板 |
| 停机条件 | 何时禁止自动继续 | 出初判后人确认；写代码停在 diff 待 review |

旁证四词各一句：

- **RAG**：先检索再生成，不是整库塞进 prompt。
- **记忆**：跨轮保留（路径、已读文件）；分短期任务态与长期用户偏好，别混成「模型永久记住一切」。
- **ReAct**：Thought → Action → Observation 的同一循环，不是另一产品。
- **评测**：抽样 case 对比初判与事后结论，不是线上全自动判对率。

产品差异在**运行位置、工具权限、责任归属**，不在「谁参数更大」：

| 形态 | 典型跑法 | 面试一句 |
|------|----------|----------|
| IDE Agent | 本机仓库 + diff | 改代码必须人看 diff |
| 终端 Agent | 多文件 + 构建测试 | 适合批处理，仍要验收 |
| 云端代理 | 远程沙箱 | 没生产用过就直说 |
| 编排（LangGraph 等） | 代码定义分支/卡点 | 步骤固定时用 |

## 原理

1. **闭环 vs 开环。** 开环补全在第一眼上下文内编完；Agent 允许「搜错了再搜」，Observation 是新事实。无工具则仍是聊天，只是 prompt 里假装能查。
2. **工具 = 受控 API。** 模型产出结构化调用（名 + 参数），运行时执行并回填。权限裁剪在工具层：只给只读日志，就不能改配置。比让模型自由写 curl 可审计。
3. **上下文经济学。** 窗口有限；RAG 裁日志（房间/时间）和代码（栈/类名）。裁错 → 在错误文件上写出自洽且错的分析——**幻觉在错误证据上更危险**。
4. **停机 = 产品安全阀。** 排查停在初判；写代码停在 diff + 约定检查。无停机 → 无限改、无限调、不可验收。
5. **多 Agent 默认非更强。** 规划/写码/审查分角色在步骤固定时常重复传上下文，贵且难归因。流水线（固定输入输出）更稳。
6. **指标语义。** 80%～90% 多指**抽样初判同因**，省的是人肉翻日志时间，不是自动发版成功率。不能把抽样准确率说成线上修复率。

专家：与自动化脚本对比——脚本路径固定、失败可重复；Agent 适合搜索空间不确定但步骤可约束的任务；两者可组合（Agent 出计划，脚本跑检查）。

## 使用与实践

排查口述链：现象 → 裁日志 → 对源码 → 初判（附路径/置信度）→ 人确认 → 才可能改。

写业务：人定范围与验收，Agent 起草，人看 diff。隐私与脱敏在工具/MCP 侧，不指望模型自觉。

不该：把 Agent 当无人值守发版；不该无日志就让它「猜原因」并改代码。

## 例子

```text
目标：房间 1001 @21:03 无信令
1. query_logs(room, user, window) -> 40 行
2. grep SocketRead 超时 -> 打开 HeartbeatWriter
3. 输出：主线程锁阻塞写心跳；建议看锁持有者栈；不改代码
```

错例：第 2 步搜到旧进程废弃类 → 模型长篇分析错类 → 人未确认就合并 PR。对例：人在步骤 3 否掉，收紧时间窗重跑，停机条件生效。

## 画面

```text
目标 → 模型选动作 → 工具 → 结果入上下文 → 再选
      → 结论 / 等人
四块：模型 | 工具 | 上下文 | 停机
```

## 常见坑与追问

1. **Agent = 大聊天模型。** 追问：多什么？工具环与 Observation。
2. **80% 是线上自动修好。** 追问：样本与指标？抽样初判同因；人仍确认。
3. **多智能体自由对话排查。** 追问：固定步骤用流水线，可验收、可对比。
4. **云端一定比 IDE 强。** 追问：责任与 diff？IDE 改动可见可回滚。
5. **RAG 等于向量库。** 追问：本质是检索降上下文；关键词+规则也常够用。
