## 问题
ANR 怎么判断、怎么看栈

## 答案
系统认为主线程没有按时处理完它该处理的事，就记一次 ANR，并抓当时各线程的栈。常见时限（面试说大约，不同版本会变）：

| 类型 | 大约时限 |
|--|--|
| 输入事件，点击和按键 | 5 秒还没处理完 |
| 前台广播 | 10 秒左右 |
| 后台广播 | 60 秒左右 |
| 前台 Service | 20 秒左右 |
| ContentProvider | 10 秒左右，注意它可能在启动路径上 |

看 `traces.txt` 或调试里的主线程栈，从上往下认三种：

1. 栈在自己的业务函数里，例如 `parseJson`、`decodeBitmap`、`database.query`。就是主线程干了重活。
2. 栈在 `monitor contention` 或等锁。主线程想拿一把被工作线程占着的锁，而对方还在 IO 里。
3. 栈停在 Binder 的 `transact`。主线程在等另一个进程返回。对方是系统服务或自己的推送进程，卡在那边。

输入 ANR 还有一个更早的原因：消息队列前面排着一条很慢的消息，点击消息轮不到。栈可能已经不在那条慢消息里了，要结合当时主线程刚刚执行完什么。原则仍是主线程只做调度和轻量 UI，网络、磁盘、解码、大 JSON 离开主线程。SDK 的同步 API 如果会碰网络，调用方一在主线程调用就会变成他们的 ANR，所以对外 API 要写明线程，耗时的做成异步。
