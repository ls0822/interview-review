## 问题
`HashMap` 为什么不安全？`ConcurrentHashMap` 安全到哪一步？

## 答案
`HashMap` 是数组，槽里挂链表。Java 8 起，一条链表长过阈值（通常再加树化条件）会变成红黑树，避免都哈希到一个槽时退化成顺序查找。扩容一般变成原来的 2 倍，用容量是 2 的幂这个特点，靠高位决定节点留在原处还是挪到「原下标 + 旧容量」。

两条线程同时 `put`：可能互相覆盖，一个 key 丢了；扩容时都在改同一条链表，旧版本里还会成环，后面 `get` 死循环。所以不能把它当多个线程共享的缓存。

`ConcurrentHashMap` 把锁的粒度缩小到桶，读多数不用拿同一把大锁。`put`、`get`、`compute` 这种单次调用是原子的。下面这个复合动作不是：

```kotlin
if (map.get(key) == null) {
    map.put(key, value)   // 两步之间别人可以插进来
}
```

要改成 `putIfAbsent` 或 `compute`。它也不允许 `null` 键和 `null` 值，用空值做哨兵会直接空指针。迭代时别的线程在改，它不会抛 `ConcurrentModificationException`，但你看到的是弱一致的视图，不保证是某一瞬间的完整快照。

`Hashtable` 和 `Collections.synchronizedMap` 是整表一把锁，能用，但并发一高就串行了。新代码不用它们。
